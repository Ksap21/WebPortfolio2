01 Overview

I built KTech Simulation to recreate the IT infrastructure of a small organization inside my Proxmox homelab. The goal is to understand how enterprise networks, centralized authentication, security policies and departmental access work together in a real environment.

The lab separates servers, employees and clients into different VLANs. A dedicated Debian router controls traffic between the networks, while Samba Active Directory provides centralized identity management and internal DNS. I have successfully enrolled a Linux employee workstation into the domain and verified domain identity resolution across VLANs.

04 Routing, NAT & Firewall

I configured static gateway addresses for each VLAN and enabled Linux IPv4 forwarding. The router uses nftables with a default-drop forwarding policy, explicit service allowances and connection tracking for established traffic.

TrafficPolicy configured
Employees / clients → DC01Selected DNS, Kerberos, LDAP and other domain service ports allowed
Client VLAN ↔ employee VLANNew routed connections denied by default
DC01 / IT-ADMIN → InternetRestricted package access through NAT; DNS via approved path
KTech → home LANNew forwarded traffic to the home IPv4 subnet blocked
WAN → routerUnsolicited incoming traffic blocked; DHCP replies permitted

These are configured policies, not a claim of exhaustive penetration testing. Traffic between hosts on the same VLAN does not traverse the inter-VLAN firewall.

05 Active Directory & Identity Management

I provisioned Samba as an Active Directory Domain Controller using an internal test domain. The server provides DNS records for locating domain services and Kerberos tickets for authentication. I configured a Linux workstation to discover and join the domain using realmd and adcli, with SSSD resolving domain users and groups.

Departmental security groups are used to organize authorization. The IT account was verified as a domain user with IT group membership rather than automatically receiving domain administrator privileges.

Workstation → DNS service discovery → Kerberos authentication
            → LDAP directory lookup → SSSD identity resolution
            → Linux user session / PAM

Domain enrollment and user identity resolution are verified. Full departmental resource permissions and endpoint access policies remain future work.

06 Troubleshooting & Validation

Inter-VLAN Connectivity

Verified the workstation routing table and an open LDAP TCP connection across VLANs. Identified that failed ICMP pings were consistent with the restricted firewall policy, rather than assuming routing was broken.

DNS & Package Access

Troubleshot installer-only APT sources and failed DNS resolution. Configured online repositories and tested internal DNS queries, including authoritative A and LDAP SRV records.

Domain Controller Startup

Inspected systemd service conditions, Samba configuration and the existing directory database before restarting the service. Avoided unnecessarily reprovisioning the domain.

Domain Enrollment

Investigated a failed realm join, confirmed Kerberos authentication and successfully enrolled IT-ADMIN. Verified active SSSD, domain identity resolution and the computer object on DC01.

07 Database & Departmental Access (In Development)

The next phase introduces MariaDB on DB01 rather than on the domain controller. The design separates identity infrastructure from business data and allows independent maintenance and security controls.

Proposed schemaExample dataIntended access
ktech_hrEmployees, leave, payrollAuthorized HR roles; sensitive tables restricted
ktech_itDevices, tickets, software assetsIT roles
ktech_operationsCustomers, orders, requestsOperations roles
ktech_sharedDepartments, announcementsApproved users with read access

The planned implementation will use MariaDB-native roles and least-privilege grants, followed by positive and negative permission tests, backups and auditing. Active Directory group membership will not automatically grant database access; application-level identity integration is a later milestone.
